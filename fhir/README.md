# FHIR R4 output and its validation

- `examples/`: FHIR R4 Bundles generated by the app's own code ([src/core/fhir.ts](../src/core/fhir.ts)) for the four demo records (`npm run fhir:examples`).
- `terminology/`: Tandem's three CodeSystems (citizen questions, answers, additional observations), which the OneAquaHealth IG does not model yet.
- `validation-log.txt`: the full output of the official HL7 FHIR validator.

## Result

**0 errors, 0 warnings** on all 7 files (4 Bundles, 3 CodeSystems), validated on 4 October 2026 with:

- the official HL7 FHIR validator, version 6.10.4,
- FHIR 4.0.1,
- the OneAquaHealth Implementation Guide built from its source, [hl7-eu/oah](https://github.com/hl7-eu/oah) at commit `b907cf0`, with SUSHI (`npm run fhir:ig`),
- online terminology checks against `https://tx.fhir.org/r4` (UCUM units included).

The Location resources conform to `LocationOah` and every Observation to `ObservationIndicatorsOah`. The remaining notes are informational: a few multi-select components carry only Tandem's question code, which the IG's preferred value set does not contain.

## Reproduce

```bash
npm run fhir:ig        # clone hl7-eu/oah and build it with SUSHI into tools/oah
npm run fhir:examples  # regenerate the Bundles and CodeSystems
npm run fhir:validate  # needs Java; downloads nothing else except terminology lookups
```
The validator jar goes in `tools/validator_cli.jar` (from https://github.com/hapifhir/org.hl7.fhir.core/releases).
